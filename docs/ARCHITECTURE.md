# Architecture

New Start is a single-instance, per-user .NET 8 WPF desktop application targeting the Windows 10.0.19041 SDK contracts and running on Windows 11. A small C++ DLL supplies Windows Composition backdrop surfaces and Core Audio integration. Optional borderless recovery uses a separate hidden instance of the same executable. The dock and menus remain native desktop windows; Explorer is never replaced or injected into.

The dock enumerates eligible top-level app windows on a one-second timer and rebuilds when its task/pin signature changes. Application menus retain their current controls while open. Shell identities merge local/read-only imported pins with running apps. Grouping is approximate for some packaged/hosted applications.

`DockGeometry` contains edge/alignment and anchored-menu calculations. `DockReservation` registers a hidden Shell AppBar on the selected primary-monitor edge and negotiates the occupied strip. Changing edges unregisters the old reservation. The visible dock is independently aligned inside the negotiated bounds, excluding its transparent hover/bounce room from reserved thickness. Menus overlay the work area. Top-centre and bottom-centre Start are horizontally screen-centred; left-centre Start is vertically centred on the dock. Other layouts follow the button and clamp to the work area.

Start prepares a cached app snapshot and warms pinned icons before interaction. Shell enumeration, Start-layout export and icon extraction run on background STA workers. Frozen image sources are cached in memory/on disk; concurrent icon requests share a task. Automatic recent destinations use a separate worker, short cache and generation checks to reject stale menu results.

Menus and settings share cached resource dictionaries and the same theme/transparency/blur values. Native backdrop companion windows sit behind transparent WPF foreground windows, with a safety timer hiding orphaned surfaces. Context menus reuse one companion and update it on position changes rather than on every frame. One compositor/dispatcher-queue service has process lifetime to avoid WinRT destruction after managed apartment teardown; individual window targets are released.

`AdaptiveAppBars` is owned by the existing dock lifecycle and shares its preferences and Start instance. It reconciles one `AdaptiveAppBarWindow` per configured display and reuses `DockReservation` with an explicit monitor provider. The 36-DIP Shell reservation is independent from the animated attached control region. Shared section transitions allow only one expansion at a time across displays. The clock spans the header grid and remains physically centred. `AppBarMaterial` draws one connected outline with concave shoulders and matching native clipping. Expansion width, height and horizontal position animate together; its palette/theme is shared with the dock, with independent AppBar blur/transparency values. Native surfaces prepare clipping and brush state before showing, use composition-only rendering and suppress default background erasure to avoid bright first frames.

Media, Core Audio, WLAN and Bluetooth adapters publish event-driven state. WLAN and Core Audio operations run off the UI thread; notifications return through the dispatcher. The existing dock polling loop is retained. `ActiveApplication` coalesces WinEvents and reads only the active or explicitly watched managed windows; it does not enumerate every window per event. `BorderlessManager` writes an identity-validated recovery journal before caption mutation. See [Adaptive AppBar boundaries and acceptance coverage](ADAPTIVE-APPBAR.md).

Preferences and caches are created under `%LOCALAPPDATA%/NewStart`. They are not bundled in source or build artifacts. Defaults are independent from the developer's live settings. Pin removal changes only New Start's local state; imported Windows pins remain unchanged.


AppBar reuses Start through a reversible content lease and shares the Settings content factory. Expansion cleanup detaches content before restoring its standalone host. AppBarBattery uses GetSystemPowerStatus and registered power notifications, unregistered at disposal.

ApplicationIdentity resolves frame/content identities and metadata; ApplicationCapabilities owns per-window discovery, caches and safe execution. Its hidden MTA UIA helper has a hard process timeout. SurfaceAppearance handles shared colour/alpha/contrast; WallpaperPalette resolves per-display files and cached clusters; BackgroundSettings provides both editors. See [context and colour](CONTEXT-AND-COLOUR.md).
