# Architecture

New Start is a single-instance, per-user .NET 8 WPF desktop application targeting the Windows 10.0.19041 SDK contracts and running on Windows 11. A small C++ DLL supplies Windows Composition backdrop surfaces and Core Audio integration. Independent recovery helpers use hidden instances of the same executable for optional borderless management and taskbar suppression. The dock and menus remain native desktop windows; Explorer is never replaced or injected into. Isolated diagnostic entry points have their own bounded lifetimes and temporary profiles.

The dock enumerates eligible top-level app windows on a one-second timer and rebuilds when its task/pin signature changes. Application menus retain their current controls while open. Shell identities merge local/read-only imported pins with running apps. `ApplicationActivation` selects an existing window before minimising, restoring or focusing it; it launches only when no matching eligible window is found. Identity resolution includes packaged targets and content/frame relationships, with compatibility limits for unusual hosts. `DockDragFeedback` supplies a non-activating pointer preview, shared insertion geometry, cancellation cleanup and pin-only removal; `DockPins` persists local ordering and imported-pin exclusions.

`DockGeometry` contains edge/alignment and anchored-menu calculations. `DockReservation` registers a hidden Shell AppBar on the selected primary-monitor edge and negotiates the occupied strip. Changing edges unregisters the old reservation. The visible dock is independently aligned inside the negotiated bounds, excluding its transparent hover/bounce room from reserved thickness. Menus overlay the work area. Top-centre and bottom-centre Start are horizontally screen-centred; left-centre Start is vertically centred on the dock. Other layouts follow the button and clamp to the work area.

Start prepares a cached app snapshot and warms pinned icons before interaction. Shell enumeration, Start-layout export and icon extraction run on background STA workers. Frozen image sources are cached in memory/on disk; concurrent icon requests share a task. Automatic recent destinations use a separate worker, short cache and generation checks to reject stale menu results.

Menus and settings share cached resource dictionaries, spacing tokens and appearance services. `UiMetrics` centralises density, padding and reduced-motion-aware fading. `ScrollPolicy` handles a wheel packet once at the nearest scroll viewer, respects Windows line/page preferences, and preserves fractional deltas; Start's page mode uses `WheelAccumulator` rather than treating every small input packet as a whole page. `AdvancedSettings` provides drill-down editing of the same validated preferences used by Standard mode. Native backdrop companion windows sit behind transparent WPF foreground windows, with a safety timer hiding orphaned surfaces. Context menus reuse one companion and update it on position changes rather than on every frame. One compositor/dispatcher-queue service has process lifetime to avoid WinRT destruction after managed apartment teardown; individual window targets are released.

`AdaptiveAppBars` is owned by the existing dock lifecycle and shares its preferences and Start instance. It reconciles one `AdaptiveAppBarWindow` per configured display and reuses `DockReservation` with an explicit monitor provider. The configured resting height, 36 DIPs by default, is reserved independently from the animated attached control region. Shared section transitions allow only one expansion at a time across displays. The clock spans the header grid and remains physically centred. `AppBarMaterial` draws one connected outline with concave shoulders and matching native clipping. Expansion width, height and horizontal position animate together. Both components use the same theme/colour processing, with independent colour, blur and transparency values and optional links for colours and effects. Native surfaces prepare clipping and brush state before showing, use composition-only rendering and suppress default background erasure to avoid bright first frames.

Media, Core Audio, WLAN, Bluetooth and power adapters publish event-driven state. WLAN, Core Audio and battery-controller operations run off the UI thread; notifications return through the dispatcher. `AppBarMedia` caches guarded playback/timeline snapshots, tracks session additions/removals and validates transport/seek capabilities before requesting commands. Sound reuses this service rather than creating a second media-session manager. `AppBarPower` coalesces Windows power events, reads aggregate WinRT battery reports and documented per-pack battery queries, and exposes one reusable connected panel. Missing capacity/cycle/lifetime data remains unavailable. The existing dock polling loop is retained. `ActiveApplication` coalesces WinEvents and reads only the active or explicitly watched managed windows; it does not enumerate every window per event. `BorderlessManager` writes an identity-validated recovery journal before caption mutation. See [Adaptive AppBar boundaries and acceptance coverage](ADAPTIVE-APPBAR.md), [media](MEDIA.md) and [power](POWER.md).

Preferences and caches are created under `%LOCALAPPDATA%/NewStart`. They are runtime data, not source configuration or bundled installation defaults. Plugin state and imported custom icons live beneath the same per-user root. Defaults are independent from any existing user's live settings. Pin removal changes only New Start's local state; imported Windows pins remain unchanged.


AppBar reuses Start through a reversible content lease and shares the Settings content factory. Expansion cleanup detaches content before restoring its standalone host. Start buttons are independently configurable in Dock and AppBar; context actions and Ctrl+Alt+S retain access when both are hidden. Plugin management and custom icon editing use dedicated themed `ConfigurationWindow` hosts.

`ApplicationIdentity` resolves frame/content identities and metadata; `ApplicationCapabilities` owns per-window discovery, caches and safe execution. Its hidden MTA UIA helper has a hard process timeout. `ApplicationMenuDiscovery` adds bounded menu-category discovery and lazy child expansion to that worker protocol; execution revalidates application/window identity and the advertised pattern. Optional adapters supplement this generic path. `SurfaceAppearance` handles shared colour/alpha/contrast; `WallpaperPalette` resolves per-display files and cached clusters; `BackgroundSettings` provides both editors. `CustomIcons` resolves stable application/component IDs with application, Dock and AppBar scopes, validates imported images before persistence, and shares frozen-image caching and change notifications. See [context and colour](CONTEXT-AND-COLOUR.md) and [application menus](APPLICATION-MENUS.md).

`PluginManager` owns API-versioned discovery, validated manifests, permission grants, lifecycle, configuration, components and capabilities. API 1 accepts data-only external link/settings manifests and explicitly registered compiled providers; it does not dynamically load untrusted scripts or binaries. Host-owned controls render normalised provider snapshots into existing Dock/AppBar surfaces. Generation checks, cancellation and bounded asynchronous refresh prevent stale or failed providers from republishing disabled components. The disabled-by-default Codex provider uses the installed official CLI's read-only app-server protocol and leaves authentication with that CLI. This is a restricted extension model, not an OS sandbox for arbitrary in-process code. See [plugin interfaces and limits](PLUGINS.md).

Preferences synchronises the independently linked background groups and notifies both BackgroundSettings editors. `TaskbarSuppression` manages only recognised Explorer taskbar visibility, with an identity-checked restoration journal and a recovery helper that must become ready before hiding begins. Background Raw Input observes Windows-key activation without consuming or remapping it; native Windows Start/taskbar behaviour remains available. `NotificationTray` requests a temporary interaction lease and focuses the verified primary Explorer taskbar so users interact with its real notification area. It does not clone or rehost third-party icons. Their lifetimes follow `DockWindow`, with foreground/show/display/Explorer notifications and the existing dock refresh fallback. See [notification-area boundaries](TRAY.md).
