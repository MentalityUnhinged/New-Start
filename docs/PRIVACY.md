# Local data and publication hygiene

New Start stores preferences, local pin identities/order, imported-pin exclusions, synced Start/app lists, icon caches, plugin state and custom icon imports under `%LOCALAPPDATA%/NewStart`. These runtime files can identify installed applications, chosen executable paths and local preferences. They are separate from source defaults and are not installation templates. Account display name and avatar are read from the current Windows account and displayed locally.

The core application contains no telemetry collection, update service or New Start account login. Launching an app, opening Windows settings or opening a user-selected recent destination delegates to Windows/the owning application, which may have its own network behaviour. New Start does not upload its settings or installed-app inventory. Explicitly enabled plugins can perform their declared operations, as described below.

When Adaptive AppBar is enabled, it reads exposed local media metadata/artwork/timeline, audio endpoints, wireless network information, paired Bluetooth device state and power telemetry. Wi-Fi APIs may invoke Windows location-consent behaviour. A Wi-Fi password is held only for passing a requested profile to Windows' per-user WLAN store, not written to New Start preferences or diagnostics. Power readings include available capacities, cycles, charging state and power-plan names; battery serial numbers/unique identifiers are neither displayed nor persisted. No power plan, media command or network connection is changed simply by opening its panel. Optional borderless management stores original caption styles and process/window identities in a local recovery journal and starts a hidden recovery instance of the same executable.

Source releases must exclude live user settings, plugin registrations/configuration, imported custom icons, caches, reusable icons extracted from installed apps, standalone account images, dumps, build intermediates, binaries and credentials. Original New Start branding and reviewed documentation images are source assets; runtime icon imports are not. New installations use code defaults, including Bottom/Centre, with no personal pin list. Review retained gallery images as well as new captures before publication: redact personal names, avatars, local/private paths, network addresses/SSIDs, account details and usage information. Installed application icons and the chosen wallpaper can be shown without publishing those personal details.

Diagnostic switches write reports locally. New isolated AppBar checks omit personal media/application titles and network/device names and use a generated profile; other diagnostics or legacy reports can still contain application paths, SSIDs, device names or track titles. Inspect/redact every report before attaching it to an issue. Build artifacts should be produced from this repository or CI; do not commit local `bin`, `obj`, `native/build`, `artifacts` or generated validation directories. Use a suitable no-reply identity for public commits.

Application-context discovery reads bounded accessibility names, control types, patterns and availability locally. It skips password controls and does not read edit-field values. Helpers use redirected local pipes and do not open network endpoints. Wallpaper analysis reads the Windows-provided image file and saves only derived colour swatches in a local hashed cache. Verification reports may reveal application identities and wallpaper colours; they remain excluded from Git.

The plugin host stores enabled state, permission grants, placement, refresh intervals and optional provider configuration in `plugins-state.json`. Data-only manifests cannot execute arbitrary binaries or read authentication files; declared link/settings actions run only after a user click. Compiled providers are trusted application code with a deliberately separate permission boundary, not untrusted code made safe by an OS sandbox. Future providers requiring credentials must use an appropriate credential store rather than this general JSON file.

The bundled Codex usage plugin is disabled by default and needs explicit consent before launching the installed official CLI and reading reported account limits. The CLI handles its existing sign-in and may contact its authorised service. New Start neither reads/copies its authentication files nor initiates login/logout. The plugin does not submit prompts, create conversations or alter allowances. Usage values remain in memory; configuration contains no copied tokens, passwords, API keys or raw account responses. Provider stdout/stderr and raw responses are not persisted in diagnostics. General ChatGPT message limits and OpenAI API billing are not inferred from Codex usage.

Custom icon selection copies the chosen image into the runtime `CustomIcons` directory and stores a stable target identity plus scope in `overrides.json`; the original source image is not modified. Imported files can retain their own image metadata. Treat both the override list and imported files as private local data. Restoring an icon removes New Start's override rather than editing application resources. Shared scrolling settings process input deltas without recording input history.

Optional taskbar suppression registers background Raw Input solely to recognise Windows-key activation. Other keyboard records are ignored; keys are never logged, persisted, uploaded, consumed or remapped. The local taskbar recovery journal stores only the window/process identity needed to restore visibility.

The native notification-area launcher temporarily exposes Explorer's real taskbar. New Start does not scrape another process's notification icons, copy their private data or impersonate their callbacks. Interacting with a real third-party tray icon delegates to its owning application and its privacy behaviour.
