# Adaptive AppBar · Beta

Enable **Adaptive AppBar** in New Start settings. New installations keep it off. It creates a top bar on every display, or only the primary display when configured. The clock is centred on the display independently of the left/right controls. The Start circle moves out of the dock and opens Start below the selected display's bar. While enabled, the dock supports Bottom and Left; enabling from Top temporarily selects Bottom/Centre. Disabling restores the remembered edge/alignment. An AppBar clock suppresses the always-visible dock clock without deleting its setting.

The bar follows New Start's shared Light/Dark/System theme and dock material palette. **AppBar transparency** and **AppBar blur** have separate whole-number sliders. Their initial values come from the existing appearance preferences, then remain independent. Both resting and expanded surfaces use these values. Zero blur hides the native companion surface and detaches its visual tree; transparency controls tint opacity. Windows high contrast/transparency policy still takes precedence.

## Hosting and interaction

Each display has one WPF host and a separate hidden Shell reservation HWND. Only the 36-DIP resting strip is registered through `ABM_NEW`, `ABM_QUERYPOS` and `ABM_SETPOS`; opening controls never changes that reservation. The shared expansion controller replaces content inside one attached surface, clips it, and animates its height from the current presentation. Rapid changes replace earlier animations. Content measurement avoids unused panel space; larger lists scroll. A single continuous outline supplies the tint, border and native blur region for both the strip and its curved expansion. Width, height and horizontal position morph together; content fades in after the material starts unfolding. There is no seam or independent flyout border. The rest of the animation window stays transparent.

Click a component again, press Escape, click another application, or leave the interactive area to collapse. Hover expansion for media is optional. Media expansion/collapse never issues transport commands. No global mouse hook, process injection or title-bar reparenting is used. Fullscreen AppBar notifications lower the bar behind fullscreen applications.

Display enumeration uses physical virtual-screen rectangles, including negative origins. Each host obtains its own window DPI before converting the fixed resting height to pixels. Display changes and `WM_DPICHANGED` reconcile hosts/reservations; removed displays release their registrations. Explorer's `TaskbarCreated` notification re-registers reservations. Shell-approved rectangles account for Explorer and other appbars. No resolution, persistent work-area setting or registry work-area modification is made.

## Controls and boundaries

| Component | Implementation | Boundaries |
| --- | --- | --- |
| Media | WinRT global media sessions; metadata, artwork, playback/session events; previous/play-pause/next and inline session selection | Only sessions exposed by their owning applications. Commands follow reported capabilities and report refusal. Artwork is optional and bounded to 8 MB. |
| Audio | Core Audio default multimedia endpoint, live endpoint/device notifications, volume and mute, inline output choices | Default-output selection uses an isolated **undocumented Windows policy COM compatibility adapter** because Core Audio has no public general setter. It validates active endpoints and verifies the multimedia default after switching. Windows updates may break this adapter; failures offer Sound settings. Communications-role defaults are left alone. |
| Wi-Fi | Native WLAN discovery, scans, ACM notifications, saved-profile connect/disconnect; custom credentials UI for open/WPA2-Personal networks | Windows location permission/service/policy can deny access. Credentials are passed to Windows' per-user WLAN profile store, never New Start settings/logs. Enterprise, WPA3, hidden-network provisioning and certificate workflows use Windows configuration. Requests remain pending until Windows reports state; failure reasons are surfaced. |
| Bluetooth | WinRT radio state/access requests/toggle, paired classic/LE device watchers and available connection properties | There is no universal paired-device connect/disconnect operation. No protocol-specific connection adapter is claimed in this beta. Devices lacking one use Windows device options; enabling a service or opening an SDP/GATT socket is not presented as a generic device connection. |
| Clock | Current culture or explicit 12/24-hour format, optional date/visibility, compact calendar | A one-second timer updates displayed time only; calendar is a local date view drawn with shared themed controls, without an opaque default calendar panel. |
| Application | Out-of-context WinEvents, active application icon/title, minimise/maximise/restore/close when style supports them | Own-window interaction preserves the last external target. Actions revalidate foreground identity, process and process start time; fullscreen/system/protected windows are excluded. |

The custom UI/compatibility layers cannot override Windows permissions or invent a device's unsupported operation. Relevant permission/configuration entry points are shown explicitly.

## Optional borderless management and recovery

**Manage compatible maximised title bars** is experimental and off by default. It removes only `WS_CAPTION` from recognised standard-frame maximised windows, retaining resizing and other style bits. Floating windows are unchanged. The initial conservative compatibility list covers standard WinForms windows and the classic `Notepad` class. Chrome/Edge, modern Explorer, WinUI/custom decorations, games, fullscreen and inaccessible/protected processes keep their frames. This is deliberately not a claim of universal title-bar removal.

Original styles and window/process identity are atomically journalled before modification. Caption bits are restored on unmaximise, exclusion, feature disable and normal shutdown, without overwriting unrelated later style changes. Exclusions accept executable names or full paths and can be added from the application section. Settings provides a recovery command.

A separate hidden instance of the same executable waits for the managing process. After an abnormal exit it restores the matching journal, validating PID, process start time, executable and class to avoid recycled HWNDs. A journal mutex and owner identity prevent an older helper from restoring a newer instance's windows. Startup also retries recovery. Unverifiable/live inaccessible windows remain in the journal. If the helper is also killed, startup recovery is the remaining mechanism; closing/reopening the affected application restores its normal frame as a final fallback. There is no administrator elevation or injected helper.

## Validation and remaining coverage

`--verify-appbar` tests every expansion, fixed work area, interrupted transitions, appearance independence, zero blur, Start anchoring and reservation release on the connected displays. `--verify-borderless` uses a disposable standard-frame process to test normal/maximised/restored states, exclusions, style preservation, orderly shutdown, journal recovery and recovery after deliberate abrupt termination. Reports and journals stay in `%LOCALAPPDATA%/NewStart`.

Development acceptance used one connected 100% display, native media metadata/artwork, native WLAN state/network list, Bluetooth radio state and volume changes restored to the prior level. Physical mixed-DPI/multi-monitor hot-plug, Explorer restart, radio toggles, real network credential/connection changes, cross-device audio switching, multiple simultaneous media applications, protected-process transitions and long-duration/driver testing remain release acceptance work. Do not present these as passed merely because compilation or synthetic checks succeed.
