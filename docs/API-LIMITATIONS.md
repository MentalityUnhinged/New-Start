# Windows API boundaries

- **Reservation:** public [Shell AppBar APIs](https://learn.microsoft.com/en-us/windows/win32/shell/application-desktop-toolbars) reserve a strip on the selected edge. The dock targets the primary display; Adaptive AppBar hosts reserve a fixed resting strip per configured display. Existing Explorer reservation is respected; expanded controls never enlarge the reservation.
- **Windows taskbar pins:** Windows has no public general-purpose pin enumeration contract. New Start reads the current user's TaskBar shortcuts and matches known identities against Taskband data without writing it. This compatibility adapter may require updates on new Windows builds.
- **Start pins:** Windows PowerShell `Export-StartLayout` supplies a read-only snapshot where supported. The last synced list is retained locally if export fails. Local New Start additions/exclusions are overlaid on that snapshot and never write Windows Start's pin database. Unpinning keeps the application in All Apps/search; pinning it again removes the exclusion. Windows Start folders and some newer pin formats may be unsupported.
- **All Apps:** `shell:AppsFolder` lists shell-registered desktop and packaged apps; unregistered executables are not automatically discoverable. Explicit local pins can still launch them.
- **Jump Lists:** [IApplicationDocumentLists](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iapplicationdocumentlists) exposes only automatic Recent/Frequent categories. User-pinned documents, custom categories and app-defined tasks are not exposed. Apps without resolvable explicit identity show standard commands only.
- **Close:** [WM_SYSCOMMAND / SC_CLOSE](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-syscommand) requests a normal close, allowing the app's own save prompts. It does not force-terminate applications.
- **Backdrop:** custom Windows Composition blur supports a variable radius; at zero the native companion is hidden entirely. Windows transparency/high-contrast preferences take precedence. Native graphics cost varies by driver/session; no universal performance claim is made.
- **Notification area:** [Shell_NotifyIcon](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw) registers an app's own icons; it provides no supported general enumeration/rehosting contract for all third-party icons. New Start offers an optional native notification-area access button independently in Dock and AppBar. It temporarily reveals/focuses the verified primary Explorer taskbar, preserving actual native icon actions, overflow, menus and tooltips. It does not display simulated or copied third-party icons. Explorer version, monitor layout and foreground-activation policy can limit access; failures are reported. See [the implemented alternative](TRAY.md).
- **Power and battery:** `GetSystemPowerStatus`, Windows battery reports, effective-mode notifications and documented battery-controller queries supply actual reported state. Firmware may omit design/full capacities, cycles or remaining time; relative units are not presented as mWh or mixed into aggregate capacities. Health is calculated only from reported compatible values. Supported power-plan selection is distinct from modern power-mode/energy-saver controls, which use working Settings links where a supported setter is unavailable. The battery indicator stays hidden when Windows reports no system battery. See [power sources and limitations](POWER.md).
- **Media:** Windows System Media Transport Controls exposes only sessions and actions published by participating applications. Title, artist, artwork, seek ranges and transport capabilities can be missing or disappear. New Start checks current advertised capabilities and reported seek bounds, handles rejection, and never interrupts playback merely to expand/collapse a panel. It does not invent a session for applications that publish none. See [media integration](MEDIA.md).
- **Account/system integration:** account display name/avatar and Known Folders are looked up locally, with generic fallbacks. The physical Windows key remains under Windows control.

Adaptive AppBar integrates native media/Core Audio/WLAN/Bluetooth services. Permissions, Bluetooth profile limitations, the isolated private audio-output compatibility adapter and the conservative standard-frame caption subsystem are documented in [its API and recovery boundaries](ADAPTIVE-APPBAR.md). Caption restoration journals are written before mutation and recovered by an independent helper/startup path; arbitrary custom title bars are not supported.

Optional taskbar suppression is implemented and is off by default. It changes the visibility of recognised Explorer-owned taskbar windows through Win32; it does not disable Explorer, replace Windows Start, modify system resolution/work-area registry values, or intercept the Windows key. A durable identity-checked journal and ready independent helper precede hiding; disable, shutdown and recovery restore recorded windows. Windows-key activation and explicit native-tray access temporarily reveal the official taskbar. Matching Shell window classes and native flyouts is a compatibility layer that can change with Windows releases, not a public API to disable every future Shell surface. If recovery/observation cannot be established, the taskbar is left available.

No administrator access, process injection or complete shell-parity claim is required by these features. Windows Start/taskbar pin databases remain read-only.

Application identity, accessibility action discovery, optional Chrome/ChatGPT adapters and wallpaper colour boundaries are detailed in [Context and colour](CONTEXT-AND-COLOUR.md). UIPI/secure desktop restrictions are respected; incomplete providers yield fewer actions. No guessed shortcuts, private application endpoints, extension installs or credentials are introduced.

The optional Finder-style application menu uses confirmed accessible menu categories and commands through the existing bounded UIA worker. Applications with custom/incomplete accessibility providers can expose only some menus or none. Opening a category discovers children lazily; execution revalidates the target and pattern. There is no claim of universal menu-bar extraction or removal of custom-drawn title bars. See [application-menu discovery](APPLICATION-MENUS.md).

Plugin API 1 supports declarative external manifests and reviewed compiled providers, with explicit permissions and independent enable/disable. It is not unrestricted third-party executable loading or an operating-system sandbox. The bundled Codex provider delegates sign-in to the installed official Codex CLI and reads the account data its app-server actually reports. Codex allowances, general ChatGPT message limits and OpenAI API billing remain distinct; unsupported fields/server versions yield unavailable information. No private HTTP endpoint, credential extraction or fabricated usage is substituted. See [plugin API and provider requirements](PLUGINS.md).

Custom icon overrides accept validated ICO/common raster files and resolve supported application/component identities with scoped fallbacks. They change New Start's presentation, not executable resources, Windows shortcuts or third-party application files. Unsupported/corrupt imports retain normal resolution. Menu scrolling normalises wheel deltas once, respects Windows preferences and accumulates fractional input; touchpad gesture delivery still depends on Windows/WPF/device drivers. Advanced controls expose existing working configuration and do not remove these platform restrictions.
